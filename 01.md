Of course. Based on the New Relic agent codebase you provided and your interest in seeing slow SQL queries and API endpoints directly within your Phoenix application, here is a design for a simple, effective, and complementary development tool.

This tool will not interfere with the New Relic agent. Instead, it will listen to the same `telemetry` events the agent uses, aggregate the data locally, and display it on a developer-only dashboard within your Phoenix app.

### Design Overview

We will create a small, self-contained performance monitor inside your Phoenix application. It will consist of:

1.  **Telemetry Handler:** A module that subscribes to Phoenix and Ecto `telemetry` events to capture endpoint timings and query statistics.
2.  **Data Store:** A GenServer that holds the collected data in memory, keeping a capped, sorted list of the slowest endpoints and queries.
3.  **LiveView Dashboard:** A set of developer-only LiveView pages to display the collected data in a simple, readable format.

This approach is lightweight, has no external dependencies, and leverages the instrumentation you already have from using Ecto and Phoenix.

---

### Step 1: Create the Performance Monitor Core

First, we'll create the modules responsible for collecting and storing the performance data.

#### **File Structure**

Create a new directory in your project: `lib/my_app_web/performance_monitor/`. Inside this directory, you will create the following files.

#### **The Data Store (`store.ex`)**

This GenServer will be our in-memory database. It will maintain two sorted lists: one for the slowest API endpoints and one for the slowest SQL queries. By capping the size of these lists, we prevent unbounded memory growth.

```elixir
# lib/my_app_web/performance_monitor/store.ex

defmodule MyAppWeb.PerformanceMonitor.Store do
  use GenServer

  @max_items 100

  # Client API
  def start_link(_opts) do
    GenServer.start_link(__MODULE__, %{endpoints: [], queries: []}, name: __MODULE__)
  end

  def add_slow_endpoint(endpoint_data) do
    GenServer.cast(__MODULE__, {:add_slow_endpoint, endpoint_data})
  end

  def add_slow_query(query_data) do
    GenServer.cast(__MODULE__, {:add_slow_query, query_data})
  end

  def get_slow_endpoints do
    GenServer.call(__MODULE__, :get_slow_endpoints)
  end

  def get_slow_queries do
    GenServer.call(__MODULE__, :get_slow_queries)
  end

  # Server Callbacks
  @impl true
  def init(state) do
    {:ok, state}
  end

  @impl true
  def handle_cast({:add_slow_endpoint, data}, state) do
    new_endpoints =
      (state.endpoints ++ [data])
      |> Enum.sort_by(& &1.duration_ms, :desc)
      |> Enum.take(@max_items)

    {:noreply, %{state | endpoints: new_endpoints}}
  end

  @impl true
  def handle_cast({:add_slow_query, data}, state) do
    new_queries =
      (state.queries ++ [data])
      |> Enum.sort_by(& &1.duration_ms, :desc)
      |> Enum.take(@max_items)

    {:noreply, %{state | queries: new_queries}}
  end

  @impl true
  def handle_call(:get_slow_endpoints, _from, state) do
    {:reply, state.endpoints, state}
  end

  @impl true
  def handle_call(:get_slow_queries, _from, state) do
    {:reply, state.queries, state}
  end
end
```

#### **The Telemetry Handler (`telemetry_handler.ex`)**

This module attaches to the telemetry events. For each event, it measures the duration and sends the relevant data to the `Store`. It uses the process dictionary (`Process.put/2` and `Process.get/1`) to associate SQL queries with the specific web request that triggered them.

```elixir
# lib/my_app_web/performance_monitor/telemetry_handler.ex

defmodule MyAppWeb.PerformanceMonitor.TelemetryHandler do
  alias MyAppWeb.PerformanceMonitor.Store

  def attach do
    # Events from Phoenix/Plug
    :telemetry.attach(
      "perf-mon-phoenix-stop",
      [:phoenix, :endpoint, :stop],
      &__MODULE__.handle_phoenix_event/4,
      nil
    )

    # Events from Ecto
    :telemetry.attach_many(
      "perf-mon-ecto-query",
      [[:my_app, :repo, :query], [:your_app, :repo, :query]], # Add all your repo telemetry prefixes
      &__MODULE__.handle_ecto_event/4,
      nil
    )
  end

  # --- Event Handlers ---

  def handle_phoenix_event([:phoenix, :endpoint, :stop], measurements, metadata, _config) do
    # Store the endpoint path in the process dictionary for Ecto events to find
    # This is a simple way to correlate events within the same request process.
    conn = metadata.conn
    full_path = "#{conn.method} #{conn.request_path}"
    Process.put(:current_request_path, full_path)

    duration_ms = System.convert_time_unit(measurements.duration, :native, :millisecond)

    # Only store endpoints that are slower than a threshold
    if duration_ms > 100 do
      Store.add_slow_endpoint(%{
        path: full_path,
        duration_ms: duration_ms,
        timestamp: :os.system_time(:millisecond)
      })
    end
  end

  def handle_ecto_event([_app, :repo, :query], measurements, metadata, _config) do
    duration_ms = System.convert_time_unit(measurements.total_time, :native, :millisecond)

    # Only store queries that are slower than a threshold
    if duration_ms > 50 do
      Store.add_slow_query(%{
        query: metadata.query,
        params: metadata.params,
        duration_ms: duration_ms,
        endpoint_path: Process.get(:current_request_path, "N/A (Background Process)"),
        timestamp: :os.system_time(:millisecond)
      })
    end
  end
end
```*Note: Remember to replace `[:my_app, :repo, :query]` with the actual telemetry prefix for your Ecto repo(s).*

#### **The Supervisor (`supervisor.ex`)**

This supervisor ensures our `Store` GenServer is started and supervises it.

```elixir
# lib/my_app_web/performance_monitor/supervisor.ex

defmodule MyAppWeb.PerformanceMonitor.Supervisor do
  use Supervisor

  def start_link(init_arg) do
    Supervisor.start_link(__MODULE__, init_arg, name: __MODULE__)
  end

  @impl true
  def init(_init_arg) do
    children = [
      MyAppWeb.PerformanceMonitor.Store
    ]

    Supervisor.init(children, strategy: :one_for_one)
  end
end
```

### Step 2: Integrate into Your Application

Now, let's hook the performance monitor into your application's lifecycle.

#### **Update `application.ex`**

Add the `PerformanceMonitor.Supervisor` to your main application's supervision tree. We'll also attach the telemetry handlers here, but only when the server is running (i.e., not during `mix test`).

```elixir
# lib/my_app/application.ex

defmodule MyApp.Application do
  use Application

  @impl true
  def start(_type, _args) do
    children = [
      # ... your other children
      MyAppWeb.PerformanceMonitor.Supervisor # Add this line
    ]

    # Attach telemetry handlers only in dev and when running the server
    if Mix.env() == :dev and System.get_env("PHX_SERVER") do
      MyAppWeb.PerformanceMonitor.TelemetryHandler.attach()
    end

    opts = [strategy: :one_for_one, name: MyApp.Supervisor]
    Supervisor.start_link(children, opts)
  end
end
```

Finally, let's create the LiveView pages to display the data.

#### **Add Developer Routes**

```elixir

if Mix.env() == :dev do

#### **Create the LiveView Modules**

Now, create the LiveView modules that will fetch and display the data.

```elixir
# lib/my_app_web/live/performance_live/endpoints.ex

defmodule MyAppWeb.PerformanceLive.Endpoints do
  use MyAppWeb, :live_view

  alias MyAppWeb.PerformanceMonitor.Store

  @impl true
  def mount(_params, _session, socket) do
    endpoints = Store.get_slow_endpoints()
    {:ok, assign(socket, :endpoints, endpoints)}
  end

  @impl true
  def render(assigns) do
    ~H"""
    <div class="container mx-auto p-4">
      <h1 class="text-2xl font-bold mb-4">Slow API Endpoints</h1>
      <p class="text-sm text-gray-500 mb-4">Showing the 100 slowest endpoints recorded since the server started.</p>

      <table class="min-w-full divide-y divide-gray-200">
        <thead class="bg-gray-50">
          <tr>
            <th scope="col" class="px-6 py-3 text-left text-xs font-medium text-gray-500 uppercase tracking-wider">Duration (ms)</th>
            <th scope="col" class="px-6 py-3 text-left text-xs font-medium text-gray-500 uppercase tracking-wider">Endpoint Path</th>
            <th scope="col" class="px-6 py-3 text-left text-xs font-medium text-gray-500 uppercase tracking-wider">Recorded At</th>
          </tr>
        </thead>
        <tbody class="bg-white divide-y divide-gray-200">
          <%= for endpoint <- @endpoints do %>
            <tr>
              <td class="px-6 py-4 whitespace-nowrap font-mono"><%= endpoint.duration_ms %>ms</td>
              <td class="px-6 py-4 whitespace-nowrap font-mono"><%= endpoint.path %></td>
              <td class="px-6 py-4 whitespace-nowrap text-sm text-gray-500"><%= format_timestamp(endpoint.timestamp) %></td>
            </tr>
          <% end %>
        </tbody>
      </table>
    </div>
    """
  end

  defp format_timestamp(milli) do
    milli
    |> DateTime.from_unix!(:millisecond)
    |> Calendar.strftime("%Y-%m-%d %H:%M:%S")
  end
end```

### Usage

After implementing these changes, start your Phoenix server. You can then navigate to `/dev/performance/endpoints` and `/dev/performance/queries` in your browser to see the reports. The data will populate as you navigate through your application and trigger API calls and database queries.
